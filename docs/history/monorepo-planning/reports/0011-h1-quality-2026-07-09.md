# Report 0011 — M15: usable ¹H (full corpus + first-order coupling)

**Date:** 2026-07-09
**Worktree:** `~/Documents/programming/chemdraw-nmr` @ `codex/nmr-plugin`
**Decision:** [ADR-0017](../decisions/0017-h1-coupling-and-full-corpus.md)

## Context

User feedback on the running ¹H predictor: no multiplets/J, and aldehyde protons not shown
"at all". Diagnosed (running the predictor): the aldehyde CHO / ethanol CH₂ / etc. were
dropped as "no database match" because the compiled DB was only **129 structures**, and the
engine had **no coupling model** at all. User chose "bigger DB + coupling layer".

## What shipped (M15)

- **Full NMRShiftDB2 corpus, pruned.** Recompiled from the full `nmrshiftdb2.nmredata.sd`
  (49,628 structures → 529,738 environments), pruned to **n ≥ 5** → 40,024 entries, **6.1 MB**
  (bundled `nmrshiftdb2.database.json`). Coverage now includes aldehydes (benzaldehyde CHO
  ≈ 9.97 ppm, n=44), etc. — no "no match" on common structures.
- **First-order coupling layer** (`providers/ocl/coupling.ts`): topology walk → class-typical
  J (vicinal 7, aromatic ortho 7.8 / meta 1.6, aldehyde 2.4 Hz) + first-order (n+1)
  multiplicity. `NmrResonance.multiplet` (label + couplings); `supportsCouplings: true`.
- **Panel:** shift table gains **Mult.** and **J (Hz)** columns.

Sample output — ethyl → t + q (J 7); isopropyl methyls → d; propanal → CHO t (J 2.4), α-CH₂
**qd** (J 7, 2.4), CH₃ t; benzaldehyde → CHO s + aromatic dt/td/tt.

## Verification

- `pnpm lint` clean; `pnpm test` → **1333 passed** (+5 coupling). Frontend build OK; the DB
  bundles into the **worker chunk (7.5 MB)** and the lazy fallback chunk — **out of `main`**
  (M10 invariant holds).
- Coupling engine unit-tested against known cases (ethyl, isopropyl, aldehyde J, benzene tt).

## Limitations / follow-ups

- The n≥5 prune + NMRShiftDB2's bias toward complex molecules means the *smallest* solvents
  (ethanol CH₂, acetaldehyde CHO) can still miss a specific environment.
- Couplings are first-order estimates only (no second-order / diastereotopic / Karplus).
- Stretch: draw first-order split peaks in the spectrum (today only the table shows Mult./J).
- The 6.1 MB DB is a large committed artifact + bundle cost; an increment engine (ADR-0017
  option 2) would avoid the data weight if revisited.
